## 1. RAG 是什么，为什么不用别的

模型的知识冻结在训练那天（W4 已验证过边界），让模型"知道"新知识有三条路：

| 路线 | 原理 | 为什么不选 |
|---|---|---|
| 重新训练/微调 | 把知识训进权重 | 贵、慢、每改一份文档重训一次，杀鸡用牛刀 |
| 长上下文硬塞 | 把全部文档塞 prompt | 窗口有限且按 token 计费；文档一多就爆 |
| **RAG** | 用到哪块查哪块，只把相关段落塞进上下文 | ✓ 便宜、实时、可溯源 |

**RAG = Retrieval-Augmented Generation（检索增强生成）**，一句话：
**回答之前先去资料库里捞几段相关的，让模型"开卷考试"。**

## 2. 向量检索的本质（W5 最重要的一个原理）

把文本交给 embedding 模型（我们用 DashScope `text-embedding-v3`），
它会输出一个 1024 维的向量——你可以理解为**在 1024 维空间里给这段话定位一个点**。
魔法在于：**语义相近的文本，点离得近**。

- "深圳今天下雨" 和 "鹏城有降雨" → 距离很近（字面完全不同！）
- "深圳今天下雨" 和 "深圳 GDP 增长" → 距离很远

于是"检索"就变成了初中几何：**把问题也变成一个点，算它和所有文档块的距离，
取最近的 K 个**。`backend/main.py` 的 `/search` 里就这几行 numpy：

```python
sims = mat @ qvec / (norm(mat) * norm(qvec))   # 余弦相似度
top_idx = argsort(sims)[::-1][:top_k]          # 取 TopK
```

这就是所有向量数据库（FAISS/Milvus/Qdrant）的核心，W6 换真向量库时你会
发现只是把这几行换成了引擎调用——**先手写一遍才配用轮子**。

## 3. 完整数据流（两半拼图）

**入库（离线，`POST /ingest`）**：

```
文档全文 → 切块(300字+50重叠) → 每块 embedding → {文本, 向量, 来源} 存库
```

**检索（在线，`POST /search`）**：

```
用户问题 → embedding → 和全部块算余弦 → TopK 块 → 作为工具结果进上下文 → 模型开卷作答
```

**切块为什么要重叠 50 字？** 一句话被切成两半时，两半都保住完整语义，
不会因为切在句中而两边都检索不到。

**为什么要记录来源（source）？** 模型回答时能注明出处——RAG 的杀手级优势
就是**可溯源**，长上下文和微调都做不到。

## 4. 端云混合架构全景（本项目当前形态）

```
┌─ Android App ──────────────┐      ┌─ FastAPI 后端（电脑）────────┐
│                            │      │                              │
│  模型(qwen-plus) ◀─ API Key│      │  /memos   备忘录（SQLite）    │
│      │                     │ HTTP │  /ingest  文档入库(embedding) │
│  工具菜单：                 │ ───▶ │  /search  余弦TopK 检索       │
│   本地手: 时间/电量/备忘录   │      │                              │
│   云端手: RemoteTools ─────┼─▶    │  Key 在环境变量，APK 零密钥    │
│   MCP手:  McpToolProvider  │      └──────────────────────────────┘
└────────────────────────────┘
```

工具在三个来源并存：本地编译期注册（@Tool）、云端 @Tool（HTTP）、
MCP 运行时发现（ToolProvider）——模型一视同仁按描述选。

## 5. 启动与联调步骤

```bash
# 电脑（项目 backend/ 目录）
set DASHSCOPE_API_KEY=sk-你的key        # Windows CMD；PowerShell 用 $env:
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000
```

```bash
# 手机连电脑 USB 时执行（端口反向代理，免配 WiFi IP）
adb reverse tcp:8000 tcp:8000
```

App 端 `RemoteTools.BASE_URL` 已是 `http://127.0.0.1:8000`（配合 adb reverse）。
同 WiFi 局域网也行：改成电脑 IPv4 地址。

**验证顺序**：
1. 浏览器开 `http://127.0.0.1:8000/health` → `{"status":"ok"}`
2. `curl -X POST 127.0.0.1:8000/ingest -d "{\"title\":\"学习计划\",\"text\":\"……你的计划书内容……\"}" -H "Content-Type: application/json"`
3. App 里问："我的学习计划是什么？" → 看 `SSE_CHAT` 日志出现
   `工具执行: searchKnowledge(...)`，回答引用计划书内容并标注来源

## 6. 作业

1. **语义检索实验**：入库你的学习计划后，问题里**不带任何原文用词**地问
   （比如入库写"周三晚上复述 LangGraph"，问"我哪天要讲课？看什么内容？"）
   —— 亲眼确认"语义匹配 ≠ 关键词匹配"
2. **TopK 实验**：把 `top_k` 调成 1 和 10，对比回答质量（太少信息不够，
   太多噪声淹没 + token 浪费——这就是 W6 评估要量化的事）
3. **断后端实验**：关掉 uvicorn 再问——观察工具报错如何变成 AI 气泡里的
   一条错误提示（Agent 容错）
